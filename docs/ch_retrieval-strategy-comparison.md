# Week 3 候选检索策略对比

## 1. 实验问题

本报告比较四种候选检索策略，回答以下问题：

1. 关键词检索能否补足纯向量对错误码、型号和数值表达的召回？
2. 查询改写能否处理 `ERR_NET_4001`、`err saf 1002` 和 `DM260` 等形式变化？
3. 头部保留重排能否在最终Top-3中保住向量路径和关键词路径的互补证据？
4. 候选层改进是否会破坏无答案问题的安全拒答？

候选评测只判断正确证据是否进入排名，不调用生成式LLM，也不等同于最终回答正确率。

| Gold问题总数 | 28 |
| 可回答问题数 | 23 |
| 无答案问题数 | 5 |
| 当前预期证据总数 | 31 |
| 最终候选深度 | Top-3 |
| Embedding模型 | `embedding-3` |
| Chroma Collection | `robot_knowledge_week3_vector_baseline` |

早期策略报告生成时，`q021` 只标注了一份预期证据；最终Gold将它修正为跨文档问题，共有两份预期证据。为了保证四种策略可比，本报告读取各策略已经保存的候选排名，并使用当前 `data/eval/gold_questions.jsonl` 和正式评分函数重新计分。

该重评分过程：

- 不重新生成Embedding；
- 不访问ChromaDB；
- 不改变任何候选顺序；
- 不调用LLM；
- 只用当前Gold重新计算命中数和指标。

## 3. 策略定义与参数

| 策略 | 向量 | 关键词 | RRF | 查询改写 | 重排 |
|---|---:|---:|---:|---|---|
| 纯向量基线 | 是 | 否 | 否 | 否 | 否 |
| 混合RRF | 是 | 是 | `candidate_k=20`、`k=60` | 否 | 否 |
| 混合RRF + 改写 | 是 | 是 | `candidate_k=20`、`k=60` | `deterministic-v2` | 否 |
| 混合RRF + 改写 + 重排 | 是 | 是 | `candidate_k=20`、`k=60` | `deterministic-v2` | `head-preserving-v1` |

`head-preserving-v1` 在最终Top-3中按以下顺序保护互补头部：

1. 保留RRF融合Top-1；
2. 保留向量路径Top-1；
3. 保留关键词路径Top-2中尚未出现的候选；
4. 剩余位置按照原RRF顺序补齐；
5. 同一Chunk只出现一次。

默认策略参数为：

| 参数 | 值 |
|---|---:|
| `top_k` | 3 |
| `candidate_k` | 20 |
| `rank_constant` | 60 |
| `fused_head_k` | 1 |
| `vector_head_k` | 1 |
| `keyword_head_k` | 2 |

## 4. 最终可比指标

| 策略 | Recall@1 | Recall@3 | Top-1完整证据召回 | Top-3完整证据召回 |
|---|---:|---:|---:|---:|
| 纯向量基线 | 0.548（17/31） | 0.742（23/31） | 0.391（9/23） | 0.652（15/23） |
| 混合RRF | 0.516（16/31） | 0.742（23/31） | 0.391（9/23） | 0.652（15/23） |
| 混合RRF + 改写 | 0.613（19/31） | 0.871（27/31） | 0.478（11/23） | 0.826（19/23） |
| 混合RRF + 改写 + 重排 | **0.613（19/31）** | **0.968（30/31）** | **0.478（11/23）** | **0.957（22/23）** |

最终策略相对纯向量基线的变化：

| 指标 | 基线 | 最终策略 | 变化 |
|---|---:|---:|---:|
| Recall@1 | 0.548 | 0.613 | +0.065 |
| Recall@3 | 0.742 | 0.968 | +0.226 |
| Top-3完整证据召回率 | 0.652 | 0.957 | +0.305 |

验收要求是候选方案相对纯向量基线完整证据召回率不下降。最终方案由 `15/23` 提升到 `22/23`，满足要求。

## 5. 指标变化原因

### 5.1 只有RRF没有改写时没有净提升

混合RRF与纯向量基线的 Recall@3 和完整证据召回相同。原因不是关键词检索没有作用，而是原始查询中的型号别名、错误码分隔符和中英文表达仍未统一。关键词路径在部分题目增加正确候选，也在部分题目挤掉原有候选，净结果为零。

### 5.2 查询改写解决表达形式差异

`deterministic-v2` 使用确定性规则完成：

- 错误码下划线、空格和连字符统一；
- `DM260` 与 `DataMan 260` 型号别名扩展；
- 中英文线缆、高压、大电流等术语扩展；
- 数字与单位格式统一。

改写后完整证据召回从 `15/23` 提升至 `19/23`。

### 5.3 头部保留重排解决多路证据竞争

RRF对两个列表中的排名进行融合，但最终Top-3仍可能被同一类相似候选占满。头部保留重排不重新计算语义相关性，而是保证向量头部和关键词头部都有机会进入最终窗口，使跨文档问题的互补证据更稳定。

重排将 Recall@3 从 `27/31` 提升到 `30/31`，完整证据召回从 `19/23` 提升到 `22/23`，同时没有降低 Recall@1。

## 7. 尚未解决的候选问题

`q027` 仍只召回两份预期证据中的一份：

```text
问题：DM260镜头保护盖清洁后怎样完成验收复测
已召回：DataMan 260清洁证据
未进入Top-3：工作站二维码读取验收规程
```

该问题需要跨文档的“设备维护 + 业务验收”关系。当前确定性改写能够识别型号和清洁语义，但没有机械规则能够稳定推断“清洁后还需要工作站验收规程”。这是后续进行查询分解、关系索引或学习型重排的主要候选。

## 8. 门控安全评测

候选胜者接入在线API之前，使用 `hybrid-evidence-gate-v1` 进行独立门控评测。

| 指标 | 结果 |
|---|---:|
| 可回答题门控放行率 | 0.957（22/23） |
| 放行且证据完整 | 21/23 = 0.913 |
| 放行但证据不完整 | 1/23 |
| 无答案错误放行率 | 0/5 = 0.000 |
| 无答案正确拒答率 | 5/5 = 1.000 |

门控没有只使用Top-1相似度，而是根据问题特征使用：

- `exact_identifier_support`：错误码等精确标识符支持；
- `model_and_lexical_support`：型号与主题关键词联合支持；
- `general_dual_path_support`：向量与关键词双路径共同支持；
- `insufficient_combined_support`：组合证据不足时拒绝。

`q007` 的正确证据已进入候选，但组合支持仍低于门控要求，因此被拒绝。`q027` 被放行但证据不完整。五道无答案题全部被正确拒绝，候选改进没有降低无答案安全性。

## 9. 最终在线回答与引用评测

最终采用“通用证据约束 + 最小充分引用”的平衡Prompt，不保留针对单题追加的等号边界或强制单证据规则。

| 指标 | 结果 | 验收目标 | 结论 |
|---|---:|---:|---|
| 可回答问题响应率 | 0.870（20/23） | ≥ 0.70 | 通过 |
| 完整证据回答率 | 0.739（17/23） | ≥ 0.65 | 通过 |
| 引用正确率 | 0.962（25/26） | ≥ 0.95 | 通过 |
| 引用覆盖率 | 0.806（25/31） | 观察指标 | 已记录 |
| 无答案正确拒答率 | 1.000（5/5） | ≥ 0.95 | 通过 |

候选完整证据召回 `0.957` 高于最终完整证据回答率 `0.739`，说明剩余差距主要发生在门控和LLM证据选择，而不是候选召回。

未完整通过的题分为四类：

- `q007`、`q025`：候选存在，但门控或LLM拒答；
- `q013`、`q026`：答案基本完整，但只选择两份Gold证据中的一份；
- `q024`：引用了正确证据，同时多选一份相关但不在Gold白名单中的页面；
- `q027`：候选Top-3本身缺少第二份必要证据。

不再通过全局Prompt补丁同时修复这些不同问题，避免提高单题指标时破坏其他问题的响应率或引用完整性。

## 10. 最终选择

最终生产候选策略为：

```text
deterministic-v2查询改写
→ 向量候选Top-20
→ 关键词候选Top-20
→ RRF(k=60)
→ head-preserving-v1(1/1/2)
→ 最终Top-3
→ hybrid-evidence-gate-v1
```

选择依据：

1. Top-3完整证据召回最高，为 `0.957`；
2. 相对纯向量基线提升 `0.305`；
3. 没有丢失基线已完整召回的问题；
4. 五道无答案题的错误放行率保持 `0.000`；
5. 最终在线回答和引用指标全部通过Week 3验收线。
