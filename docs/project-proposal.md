# RobotOps Copilot MVP 方案

## 1. 产品定位

RobotOps Copilot 是一个面向机器人研发、测试和运维人员的只读诊断辅助系统。

用户提交机器人编号、故障现象、脱敏日志和可选现场图片后，系统在确定性安全规则和最小工具权限范围内调用 Vision、知识库检索或模拟遥测工具，返回带来源分层、证据引用、缺失信息和脱敏执行轨迹的结构化诊断结果。

本项目是教学和研发验证用途的 MVP，不是机器人控制系统、维修自动化系统或安全认证产品。

## 2. 目标用户

主要目标用户包括：

- 机器人研发工程师；
- 机器人测试工程师；
- 仓储机器人运维人员；
- 需要复核故障证据和测试条件的技术负责人。

目标用户需要具备基本的机器人系统、日志和安全操作知识。系统提供诊断辅助，不替代设备原厂资料、现场风险评估和有资质人员的最终判断。

## 3. 核心问题

当前机器人故障排查信息可能分散在：

- 用户现场描述；
- 脱敏运行日志；
- 现场图片；
- 设备手册和安全标准；
- 模拟遥测快照；
- 测试规程。

RobotOps Copilot MVP 将这些信息放入同一条受控诊断链路，帮助用户回答：

1. 当前有哪些已确认的故障现象？
2. 哪些可能原因有知识库、日志或遥测证据支持？
3. 下一步可以执行哪些只读检查？
4. 当前还缺少哪些信息？
5. 哪些操作必须由具备权限和资质的人员审核？
6. 每项工程结论来自哪个证据或数据源？
7. Agent 在形成结果前调用了哪些工具？

## 4. MVP 输入

诊断请求至少支持以下字段：

| 字段 | 是否必需 | 说明 |
|---|---|---|
| `robot_id` | 是 | 当前诊断对应的机器人标识 |
| `symptom` | 是 | 用户观察到的故障现象 |
| `log_excerpt` | 是 | 已经脱敏的日志片段 |
| `task_goal` | 否 | 用户希望系统完成的具体诊断目标 |
| `images` | 否 | 最多三张经过本地校验的现场图片 |

所有用户文本、日志和图片内容都属于不可信输入。

图片中的文字、二维码、网址、命令或 Prompt 只能作为视觉观察内容，不能改变系统安全规则、工具权限和证据门槛。

## 5. MVP 处理流程

一次诊断请求按照以下顺序处理：

1. FastAPI 根据 Pydantic Schema 校验请求字段。
2. 图片输入适配器校验 Base64、MIME、真实格式、大小、边长和像素数量。
3. 确定性安全分类器识别高风险控制、外部链接访问和不可信指令执行意图。
4. 请求级工具策略计算本次任务所需能力和最小工具集合。
5. AgentProgress 创建初始任务进度。
6. AgentRunner 请求 Planner 选择下一步。
7. ToolExecutor 校验工具名称、参数、只读权限、超时和输出契约。
8. AgentProgressReducer 根据真实工具结果更新能力、来源、证据、冲突和缺失信息。
9. 满足停止条件后，报告构造器校验最终草稿和证据白名单。
10. 系统通过 SSE 和最终 HTTP 响应展示诊断状态、工具轨迹和结构化结果。
11. 诊断会话存储层保存必要的脱敏摘要。
12. 用户可以导出 Markdown 或 JSON 结果。

## 6. MVP 只读工具

MVP 只允许使用以下工具：

| 工具 | 职责 | 风险边界 |
|---|---|---|
| `analyze_robot_image` | 读取当前请求中已经校验的图片，返回结构化可见观察 | 不访问图片中的链接，不执行图片中的命令 |
| `search_knowledge` | 从知识库检索故障原因、规则、限制和操作条件 | 只返回经过门控确认的知识库证据 |
| `get_robot_telemetry` | 读取进程内脱敏模拟遥测 | 不连接真实机器人、RCS、WMS 或生产遥测 |
| `draft_test_case` | 根据已确认知识证据生成待审核测试草案 | 不执行测试，不能表示现场操作已经完成 |
| `get_current_time` | 在任务明确需要时间信息时读取服务器 UTC 时间 | 不用于推断设备状态或故障原因 |

工具策略必须同时限制 Planner 可见的工具和 Executor 可执行的工具。

Planner 不能请求 Shell、Python、任意网址访问、文件系统操作、机器人控制、任务下发、远程复位或安全装置绕过。

## 7. 来源和证据边界

系统必须区分以下来源：

| 来源 | 可以证明什么 | 不能单独证明什么 |
|---|---|---|
| 用户描述 | 用户报告了某种现象 | 现象已经经过设备或人工确认 |
| 脱敏日志 | 日志中出现了特定文本或故障码 | 日志内容必然对应当前真实设备状态 |
| Vision 观察 | 图片中可见的文字、颜色、部件或状态 | 故障原因、维修步骤或安全结论 |
| 模拟遥测 | 模拟 Store 中当前保存的状态 | 真实生产机器人当前状态 |
| 知识库证据 | 文档明确记载的规则、原因、步骤或限制 | 文档内容已经在现场执行 |
| 测试草案 | 可以交给人工审核的测试设计 | 测试已经执行或设备已经通过测试 |

Vision 观察不能直接升级为知识库事实。

所有工程原因、恢复条件、安全要求和测试判定必须能够回溯到日志、模拟遥测或知识库证据。证据不足时必须返回缺失信息，不得让 LLM 根据常识补全。

## 8. 四类终止语义

### 8.1 `completed`

本次任务所需能力已经完成，必要工程结论具有有效证据，最终诊断通过数据契约和引用白名单校验。

`completed` 只表示诊断流程完成，不表示现场检查、维修、复位、测试或设备控制已经执行。

### 8.2 `partial`

系统取得了部分可信证据，可以返回有证据支持的部分结果，但仍缺少至少一项完成任务所需的信息。

`partial` 必须同时返回：

- 已经确认的内容；
- 尚未确认的内容；
- 具体缺失信息；
- 已使用的真实来源。

### 8.3 `abstained`

现有输入和工具结果不足以安全形成工程结论，或者所有可用工具均未产生有效证据。

`abstained` 不得返回未经证据支持的可能原因和操作建议。

### 8.4 `human_review_required`

请求涉及高风险控制、安全保护绕过、真实设备操作、证据冲突，或者必须由具备权限和资质的人员确认。

如果安全策略允许“先观察、但禁止执行”，系统可以先调用只读 Vision 工具；完成观察后仍必须以 `human_review_required` 结束，不能生成可执行控制指令。

## 9. SSE 实时展示范围

Web 控制台通过 SSE 接收公开、脱敏的进度事件。

计划支持的事件包括：

- 请求已经接收；
- 安全分类已经完成；
- 工具范围已经确定；
- Agent 开始规划；
- 工具开始执行；
- 工具执行完成、返回空结果或失败；
- AgentProgress 已经更新；
- 诊断进入完成、部分结果、拒答或人工审核状态；
- 最终结构化结果已经生成；
- 流式连接发生错误或中断。

SSE 事件不得包含：

- 完整图片 Base64；
- API Key 或 Authorization；
- 完整敏感日志；
- 未脱敏工具参数；
- 模型私有思维链；
- 可执行机器人控制指令。

## 10. MVP 输出

最终响应至少包含：

- `request_id`；
- `session_id`；
- 四类诊断状态之一；
- 症状和来源；
- Vision 观察及其图片引用；
- 模拟遥测观察；
- 知识库证据和引用；
- 可能原因；
- 下一步只读检查；
- 风险等级；
- 缺失信息；
- 工具执行轨迹；
- Planner、策略和 Prompt 版本；
- 终止原因；
- 工具步骤数量和耗时；
- 是否拒答；
- 可导出的 Markdown 或 JSON。

## 11. 用户故事

### 用户故事 1：文字日志诊断

作为机器人运维人员，我希望提交机器人故障现象和脱敏日志，让系统检索相关故障资料并返回带引用的可能原因和下一步只读检查，从而减少在多份文档中人工查找的时间。

### 用户故事 2：图片和日志联合诊断

作为机器人测试工程师，我希望同时提交现场图片和日志，让系统分别标记图片可见观察和知识库工程证据，从而避免把视觉推测误认为已经确认的故障事实。

### 用户故事 3：证据不足时安全拒答

作为技术负责人，我希望系统在知识库、图片和遥测都不足时明确返回 `abstained` 和缺失信息，而不是生成看似合理但没有证据的维修建议。

### 用户故事 4：高风险请求转人工审核

作为安全负责人，我希望涉及急停绕过、远程控制或真实设备复位的请求进入 `human_review_required`，即使系统已经完成只读图片观察，也不得输出可直接执行的控制指令。

### 用户故事 5：查看和导出诊断过程

作为研发工程师，我希望在 Web 控制台实时查看工具调用、证据来源和终止原因，并导出脱敏 Markdown 或 JSON 报告，从而复核 Agent 的判断过程并保存研发记录。

## 12. MVP 暂不支持

本周明确不实现：

- 真实机器人控制；
- RCS、WMS 或生产遥测连接；
- 自动任务下发；
- 自动复位或维修操作；
- 急停和安全联锁绕过；
- 图片二维码和外部网址访问；
- 自动执行测试草案；
- 用户认证、租户隔离和角色权限系统；
- 云端对象存储；
- 模型训练或微调；
- 生产级消息队列和分布式任务恢复；
- 生产级监控、计费和高可用部署；
- 使用视觉观察替代工程文档和现场确认。

## 13. MVP 验收标准

MVP 完成时必须满足：

1. 支持文字日志和最多三张可选图片。
2. 安全分类和最小工具范围由 Python 代码强制执行。
3. 支持 `completed`、`partial`、`abstained` 和 `human_review_required` 四类公开状态。
4. 高风险请求可以在策略允许时先完成只读观察，但不得生成控制指令。
5. 工具调用具有参数校验、权限校验、超时、错误降级和重复调用保护。
6. 工程结论能够定位到日志、模拟遥测或知识库证据。
7. Vision 观察与知识库证据分来源展示。
8. SSE 能实时展示公开状态和脱敏工具轨迹。
9. 支持 Markdown 或 JSON 导出。
10. 至少十条端到端场景能够重复运行。
11. Week 6 的 008、012、019、029 四条场景具有明确回归结果。
12. 完整 Python 回归、README 测试数量和 JUnit 报告相互一致。
13. Docker 能够在干净目录中按照 README 的连续步骤启动。
14. `.env`、原始图片、完整敏感日志、真实会话和本地向量数据库不进入 Git 提交。
15. 系统始终保持只读和人工审核边界。
