# Week 2 RAG 与裸 LLM 对照实验公开摘要

## 1. 实验目的

实验比较同一个生成模型在两种输入条件下的行为：

```text
RAG组：问题 + 当前知识库检索证据
裸LLM组：问题 + 谨慎回答规则
```

裸 LLM 不会看到 Gold 参考答案、预期证据或 RAG 响应。完整回答和原始引用只保存在本地，本文只公开结果分类、耗时和工程结论。

## 2. 实验配置

| 配置 | 值 |
|---|---|
| LLM 模型 | `deepseek-v4-flash` |
| Embedding 模型 | `embedding-3` |
| Chroma Collection | `robot_knowledge_v4` |
| Top-K | 3 |
| RAG 门控阈值 | 0.60 |
| 实验题目 | q014、q020 |

## 3. 初始实验结果

| ID | Gold类型 | RAG状态 | RAG引用数 | RAG端到端耗时 | RAG检索耗时 | 裸LLM耗时 |
|---|---|---|---:|---:|---:|---:|
| q014 | 多跳可回答 | 已回答 | 2 | 11400.6 ms | 754.3 ms | 8595.8 ms |
| q020 | 无答案 | 已拒答 | 0 | 276.1 ms | 218.1 ms | 2238.4 ms |

耗时是单次真实网络实验结果，会受到服务商负载、网络和模型随机性的影响，不能作为稳定性能基准。

## 4. q014 观察

RAG 找到了两条项目专有证据，并返回可以定位到真实 Chunk 的引用。裸 LLM 没有项目证据，混入了当前语料不支持的通用温度、恢复条件和测试建议。

初始 RAG 回答虽然引用正确，却遗漏了证据中的否定性安全约束。这说明：

```text
检索正确 + 引用正确
不等于
回答语义一定完整
```

Prompt 随后增加了保留禁止、强制、前置条件和数值阈值的规则。q014 V2 明确保留“不允许为了测试而真实堵转电机”的安全边界。

V2 单次耗时记录：

| 项目 | 结果 |
|---|---:|
| RAG端到端耗时 | 13322.1 ms |
| RAG检索耗时 | 874.7 ms |
| 裸LLM生成耗时 | 21755.0 ms |

## 5. q020 观察

q020 需要实时机器人状态，而当前知识库只包含静态文档。

RAG 在相似度门控后返回结构化拒答和空引用，没有调用生成式回答 LLM。裸 LLM 也给出了谨慎结论，但仍执行了一次生成请求。

该案例说明代码层门控可以提供：

- 更确定的拒答契约；
- 空引用保证；
- 更低的无答案路径费用；
- 不依赖模型自行判断是否知道实时状态。

## 6. 结论

RAG 的主要价值不是让模型回答所有问题，而是提供项目证据、可追溯引用和代码层拒答。实验也暴露出生成层仍可能遗漏关键安全限制，因此必须同时使用 Prompt、Schema、证据白名单、自动化测试和人工评测。
