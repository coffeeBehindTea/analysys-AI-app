## 3. 分类定义

### `baseline_success`

正确证据进入需要的 Top-K，在线 API 也正确回答。

成功题仍必须保留在台账中，作为后续混合检索不得破坏的回归对照。

### `parsing_missing`

原始文档中存在答案，但 Loader 生成的 `SourceTextSegment` 中没有对应内容。

判定前必须同时证明：

1. 原始文件确实包含目标内容；
2. 解析结果中确实不存在目标内容。

扫描 PDF 无文字层、复杂表格、多栏错序或 OCR 缺失可能造成此类问题。

### `chunk_boundary_break`

目标内容已经解析出来，但切分后：

- 问题和答案被拆到不合理的多个 Chunk；
- 标题与正文失去联系；
- 数值和适用条件被分开；
- 单个 Chunk 无法形成完整证据。

不能只因为问题是 `multi_hop` 就判定为切分失败。跨文档问题本来就需要多项证据。

### `identifier_or_error_code`

问题包含故障码、产品型号或其他结构化标识符，但纯向量检索没有优先返回精确匹配内容。

典型形式包括：

```text
ERR-SAF-1002
ERR-NET-4001
DataMan 260
TEST-NAV-001
```

这类标识符具有很强的字面意义，适合关键词或精确匹配，不应完全依赖语义向量。

### `semantic_ambiguity`

系统找到了主题相关内容，但它不能完整支持答案。

常见情况包括：

- 中文问题检索英文文档时定位到错误章节；
- 充电温度与运行温度混淆；
- 相关产品页面压过真正参数页面；
- 一般安全说明压过具体故障处理步骤。

### `gate_rejection_with_evidence`

正确证据已经完整进入 Top-K，但在线门控只检查 Top-1 相似度，最终拒绝调用 LLM。

该分类要求：

1. `fully_recalled_at_3=true`；
2. Top-1 相似度低于在线阈值；
3. 在线结果为拒答。

### `truly_unanswerable`

问题要求的信息不在当前静态知识库中。

例如：

- 真实仓库设备型号；
- 实时机器人位置；
- 当前电量；
- 当前订单；
- 未经证据证明的厂商关联。

正确行为是拒答并返回空引用。

### `pending_verification`

现有报告不足以排除解析或切分问题时，暂时使用该分类。

不得为了尽快填满台账而强行选择一个原因。

## 4. 归因原则

1. 从上游向下游检查，选择最早被证实失败的层。
2. 不能只根据相似度高低判断解析或切分是否成功。
3. 正确证据进入 Top-3，可以证明该证据至少已经完成解析、切分、向量化和存储。
4. Top-3 没有正确证据，不能直接证明解析缺失，必须继续检查目标 Chunk 是否存在。
5. 无答案题被拒答是正确结果，不属于系统失败。
6. 成功题继续作为回归样例，优化后不能退化。
7. 一题只记录一个主要分类，其他现象写入“次要观察”。

## 15. q008 归因

问题要求同时回答：

- 充电温度范围；
- 放电温度范围。

正确证据位于：

```text
victron energy_Manual_Lithium_Smart_Battery_en.pdf
page: 4
section: 1.2 Charge and discharge warnings
```

这些错误候选也包含“电池”“温度”“充电”等相关语义，但不能完整回答两个不同的温度范围。

主要分类：

```text
semantic_ambiguity
```

次要原因：

```text
numeric_range_confusion
```

这道题说明：

```text
主题相关
不等于
证据完整
```

特别需要注意：

```text
q008 Top-1相似度 = 0.598
当前门控阈值       = 0.600
```

二者只相差 0.002。如果为了放行 q001、q006、q010 而直接降低阈值，q008 的错误证据也可能被放行。

因此不能把所有拒答问题都归因于门控过严。

后续候选方案：

- 将中文问题改写为 `charge temperature range` 和 `discharge temperature range`；
- 对 `charge`、`discharge`、`temperature` 和 `range` 进行关键词匹配；
- 让重排器检查候选是否同时覆盖充电与放电两个条件；
- 对包含单位、上下限和范围结构的候选增加完整性判断。

## 16. q009 归因

问题包含精确故障码：

```text
ERR-SAF-1002
```

正确证据位于：

```text
仓储机器人故障说明.txt
section: ERR-SAF-1002
```

历史结果却更偏向：

- 急停测试规程；
- 通用安全标准；
- 其他语义相关的安全内容。

这些内容与安全主题有关，但不能替代具体故障码章节中的排查和复位流程。

主要分类：

```text
identifier_or_error_code
```

该问题不是“模型完全不理解安全语义”，而是纯向量检索没有给予精确字符串足够的排序优势。

错误码具有以下特征：

- 字符串短；
- 结构固定；
- 每个字符都有区分意义；
- 语义相似并不能代替精确相等。

例如：

```text
ERR-SAF-1002
```

不能因为都与安全有关而被以下内容替代：

```text
ERR-NAV-2001
ERR-DRV-3005
通用急停规则
```

后续候选方案：

- 使用正则表达式提取故障码；
- 对标准化后的故障码执行精确匹配；
- 增加关键词或 BM25 检索；
- 将精确命中的 Chunk 与向量候选进行融合；
- 对精确故障码命中设置明确、可测试的排序规则。
